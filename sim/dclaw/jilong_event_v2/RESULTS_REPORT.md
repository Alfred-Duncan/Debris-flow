# Phase 2C results: evidence-locked short-pulse inflow

## 1. Station location and route ordering

Seqiong (色穷) was not geolocated. The downloaded hydrology product contains terrain hydrology rasters only, not station coordinates or monitoring metadata. Accordingly, model-entry → Seqiong, Seqiong → port, and the spatial order of the station cannot be reported without invention. The existing model-entry → port route diagnostic is about **18.27 km** (17.624 km mapped river plus 0.646 km connector). See [`docs/EVENT_TIMELINE_LOCK.md`](../../../docs/EVENT_TIMELINE_LOCK.md).

## 2. Inflow implementation

V2 uses a finite case-level custom left-boundary condition, not a moving `qinit` mass. At the grid-aligned transect 29.9 m upstream of the existing model entry it injects a 256 m-wide triangular debris-flow pulse, simulated for 600 s with output every 10 s. Only `Q_in_peak` and `T_in` vary. The fixed, provisional D-Claw boundary state is described in `SOURCE_MODEL.md`; none of its depth, velocity, or composition values are claimed observations.

## 3–5. Mandatory mechanism control

Run 1 used Qpeak=30,000 m3/s and T=60 s, with entrainment off. It did not reach the port in 600 s; maximum domain speed was 48.22 m/s.

Run 2 used the same source with documented D-Claw entrainment on: method 1, rate 0.2, `me=0.65`, and a fixed 2 m entrainable layer. It produced the same port result (not reached, peak port discharge 0) and exposed 0 m3 of accumulated entrained volume. Thus, under this one provisional configuration, turning entrainment on did **not** materially improve propagation. This is a model-mechanism result, not evidence that the event lacked progressive entrainment.

## 6. Best candidate

No candidate is a credible event reconstruction. The best numerically screened mechanism-enabled candidate is **run 2** only because it retains entrainment and avoids the high speeds generated by later forcing attempts. It still fails the essential port-arrival condition.

## 7–8. Timing comparison

Seqiong → port time is unavailable: the station has no coordinate and the 10:55 interruption is not an exact front-arrival measurement. No case reaches port, so no model-entry → port arrival is obtained. The result is incompatible with using the approximately 7 min full source-to-port reconstruction as event context: even with a 600 s window, the chosen downstream representation fails to reach the port.

## 9. Port peak-discharge comparison

Every run has a calculated port-cross-section peak of 0 m3/s because no wet/debris material reaches that cross section. This does not approach the lower-confidence early rapid-assessment soft value of about 3–5e4 m3/s.

## 10. Main remaining mismatch

The required failure is simultaneously to transport the short pulse to port on the 600 s event-consistent horizon without generating source-forced 88–118 m/s domain speeds. Runs 3 and 4 are rejected by a transparent **numerical screening** flag (`domain_max_speed > 60 m/s`), not by an asserted physical velocity limit; their fields remain finite but their velocities result from attempts to force arrival. Their source-only changes did not solve the mismatch. No material parameter, grid, or constitutive parameter was tuned.

## Run record

`CANDIDATE_RUNS.csv` is the authoritative numerical record. All four solver executions reached t=600 s without NaN/FPE. Reported runtime is wall time for input generation, run, and postprocessing.
